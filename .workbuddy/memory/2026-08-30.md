## ESP32-S3 + NestJS 语音链路：TTS 回复时 WebSocket 断连（socket_close）排查

- 现象：正式环境（域名 + Nginx 反代 → 内网端口）TTS 回复播到第二句附近，后端打印
  `[voice] cancel turn turnId=N reason=socket_close`。4 轮样本中 1/2/4 断，第 3 轮（短回答 16 字）正常完成。
- 关键结论：**后端不是主动关闭方**。服务端唯一 close 入口 `voice-session.gateway.ts:276`
  `entry.socket.close()`，只由「空闲 120s 超时」和「新连接顶旧连接」两处触发，两者都会打日志，
  而现场日志里都没有 → close 来自设备端或 Nginx。
- 服务端 `sendBinary`（`voice-session.gateway.ts:242-248`）无 `bufferedAmount` 检查、无 send callback；
  网关完全没有 ping/pong 心跳。
- 设备端缓冲：解码队列 96 帧 × 60ms ≈ 5.76s（`device_voice_client.h:117`）
  + 播放队列 5s（`pcm_playback_queue.h:27`）= 约 10.7s。
  服务端 TTS rtf 0.23~0.45，即 2.2~4 倍实时速度下发，长回答必然打满缓冲。
- 固件背压设计（`device_voice_client.cc:414-439` 注释）依赖「WS 接收任务停读 → TCP 窗口收窄 →
  服务器节流」，但中间插入 Nginx 后该背压被代理缓冲吸收，传不回服务端。
- 设备端另一条自断路径：`device_voice_client.cc:370-380`，只要 `DecodeBinaryFrame`
  返回非 kOk（如 kNotEnough=1）就 `HandleSocketDisconnected(..., "bad_frame")` 主动断连；
  固件未做 WS 分片重组。
- 给出的排查路径（成本从低到高）：① 服务端 close 事件补打 code/reason；
  ② sendBinary 记录 socket.bufferedAmount；③ Nginx location 补
  proxy_read_timeout/send_timeout 3600s + proxy_buffering off + tcp_nodelay on；
  ④ 取设备端 DeviceLog / 串口（看 reason 是 bad_frame 还是复位）；⑤ 内网直连绕开 Nginx 做二分。
## 已实施加固（后端已改完并通过测试，待正式环境验证）

后端 `voice-session.gateway.ts`：
- close 事件补打 `code` + reason（判据：1006=传输层中断 / 1000=设备正常close / 1002·1007=协议错）；error 事件打日志。
- 新增心跳：`VOICE_HEARTBEAT_INTERVAL_MS`（默认 20s）+ `VOICE_HEARTBEAT_MAX_MISSED`（默认 2）。
  心跳**不刷新** lastActiveAt，保持原 120s 空闲关闭语义不变。
- `sendBinary` 增加：send callback 捕获异步错误 + try/catch 吞同步异常（否则会顺着 pacing 定时器
  回调冒泡成未捕获异常打挂 pm2 进程）+ bufferedAmount 观测（超 1MB 每 5s 告警）+ 记录 peakBacklog，
  连接回收时打印。返回 `boolean | void`，false 表示不可写。
- 新增 `VoiceClientEntry` 类型统一 entry 结构。

后端 `voice-turn.service.ts`（核心修复：下行 pacing）：
- 新增输出泵：`enqueueOutputFrame` / `pumpAudioOutput` / `clearOutputPump` / `flushPendingFinale`。
  `sendOpusPacket`、`sendOutputPcm` 由"立即发"改为"入队按音频时长排程发"，下行速率压回 1 倍实时。
- 计划发送时刻 = `audioFirstFrameAt + audioPumpedMs - pacingBudget`；budget 默认 1500ms，
  60s 后放宽到 8s，75s 后 600s（≈全速）—— 防止拖过设备侧 120s 看门狗
  （`headless_voice_controller.cc:45/649`）。
- `completeTurn` 拆分：opusFramer.flush 只入队，`asr.final`/`turn.done` 改为挂在 `pendingFinale`，
  等音频排空后由 `sendTurnFinale` 发送（设备收到 turn.done 即进入等待排空，早发会截断尾音）。
  `persistTurnMessages` 仍在 completeTurn 里同步做，不延后落库。
- 新增 timeline 事件 `turn.finale`；`turn.complete` 增加 `audioMs` / `pendingFrames`。
- `cancelTurnInternal` 调 `clearOutputPump` 清定时器与残余帧。
- 开关：`VOICE_TTS_PACING_ENABLED=false` 可一键退回"拿到就发"。默认开启。
- 帧时长：opus 固定 60ms/帧；PCM 按 `payload.length / 48` 计算（24kHz·16bit·mono）。

固件 `device_voice_client.cc`：
- `bad_frame` 分支补 DeviceLog 诊断（rc 文字含义 + 帧长度 + 头部前 8 字节 hex），零行为变更，
  目的：不接串口也能在网页日志里区分 `not_enough`（WS 分片未重组）与 `bad_magic`（帧错位）。
- 新增 `#include <cstdio>`（snprintf）。
- **未做** WS 分片重组：本地缺 managed_components，拿不到 `web_socket.h`，无法确认 OnData 的
  分片语义，盲改有把多个独立帧拼接而损坏数据的风险。待用户拉取依赖后确认再改。

新增文件：`backend/deploy/nginx-voice-websocket.conf`（可直接 include 的 location 片段）。
